# Phase 3

Results are in `analysis/phase3_metrics.json` (sha256 `e044252bdd4c58dea9280565bc4e32832c8d59724d52f939e7f19f7d17dd4fa8`) and `phase3_report.md`. `analysis/survival_p3.json` (sha256 `6c222258f13d9a1b485d9ac6caff73620e8146228f2086b9d5ad2dceba01835f`) is the PROCEED survival-ratio bootstrap and the US R1-1 recount that drops historic stop2_136. `make reproduce` regenerates both JSON files from `run/results_*.jsonl` and the committed manifests. The report is generated by `analysis/make_report_p3.py`. The metrics file adds a `status` field from `whostop.gate`; the file before that field was sha256 `f9690fd943d4cd3d10b4b4ec282dd84bfbccd786b4938760300e497de5583a32`.

`phase3/private/` (renderer), stimulus images, and `run/server_*.log` are not in this tree.

Already here:

- `PREREG.md`: the Phase 3 plan, fixed before any Phase 3 model run (its SHA-256 is logged in `DEVIATIONS.md`). It is a pre-specified plan on bases already seen in Phase 2, not a preregistration of fresh data.
- `DEVIATIONS.md`: append-only deviation and hash log.
- `ERRATA_phase2.md`: corrections to the Phase 2 report.
